## 它是什么

给跑在 DSH 上的 AI 助手加一层长期记忆。它把对话沉淀成**卡片**，然后在每一轮里决定*该想起什么*——靠的是四股互相拉扯的力，而不是单纯的关键词匹配。

核心想法：**记忆不是存储问题，是选择问题。**
把所有东西都存下来很容易。难的是决定什么该浮上来、什么该安静地淡下去。

---

## 为什么还要再造一个记忆系统

市面上大多数「AI 记忆」实现，是这两种之一：

| 做法 | 问题 |
|---|---|
| 往上下文文件里不断追加 | 无限膨胀，最后根本塞不进 |
| 向量库 + top-k 检索 | 不区分重要度和时间；去年随口一句和昨天的决定，召回强度一样 |

这个插件把回忆当成**带衰减的排序问题**：

- 被标记为重要的决策，几个月后还找得到。
- 随口一句，几周后就淡了——除非它一直在被用到。
- 检索会记录**采纳**：被搜出来但从没被用过的卡，不会因此涨权重。

## 它怎么工作

### 四层结构

```
L0  原始对话        conversations/*.jsonl   每一轮都在，可回放
L1  事实卡          records/*.jsonl         按窗口提炼的事实
L2  长期记忆        engrams.jsonl           持久卡片 + 超图
L3  人格与公理      soul.md / 宿主公理      永不衰减
```

L0 / L1 是**流水**，会老去。L2 承载长期主线。L3 是焊死的。

### 四股力

每张卡被四个力同时拉扯：

| 力 | 含义 |
|---|---|
| **相关度** | 与当前查询的 BM25 / 向量 / 图邻近度 |
| **重要度** | 长期看有多要紧（纠错和决策排得高） |
| **新鲜度** | 指数衰减，半衰期按卡而定 |
| **强度** | 它实际上被用过多少次 |

半衰期由重要度推导：

| 重要度 | 半衰期 |
|---|---|
| 公理 | 永不衰减 |
| ≥ 0.80 | 180 天 |
| ≥ 0.55 | 60 天 |
| 其余 | 21 天 |

### 检索管线

```
查询
  -> BM25 过一遍卡片池          （永远开着，零依赖）
  -> + 向量相似度               （可选，任何 OpenAI 兼容的 embedding 端点）
  -> + 超图扩散                 （可选，沿 episode / 实体边扩散）
  -> 四股力重排
  -> 按预算注入到本轮
```

BM25 之后的每一级都能单独关掉。**向量服务挂了就退化成 BM25，绝不会有「检索不可用」这种结局。**

### 派单回执状态机

这个功能不是设计出来的，是被真实使用逼出来的：当你把一件事派给别的 agent，你需要知道*它到底怎么了*，而不只是「发出去了」。

`dispatch_send` -> `dispatch_scan` -> `dispatch_close`，把一单任务跟踪过八个状态：

```
pending -> confirmed -> in_progress
                          |-> busy_ignored      收到了但没处理
                          |-> delivery_lost     压根没投到
                          |-> orphaned          干完了但回执丢了
                          |-> dead_target       目标真死
                          |-> undetermined      读不到，不猜
                                      -> closed  销账
```

不可动摇的一条：**`inactive` 是健康的空闲态，永远不等于「死了」。** 把两者混为一谈会造出假警报，而假警报比没有警报更糟。

## 安装

### 前置条件

- **Node.js ≥ 20.18**
- **DSH ≥ 0.1.7-rc.1** —— 这是一个 DSH 插件，不是独立守护进程。它需要宿主提供 `ctx.tools`、`ctx.sessions`、`ctx.sessionPersistence`，以及可选的 `ctx.agentTeams`。

### 步骤

```bash
git clone <本仓库> dsh-unified-memory
cd dsh-unified-memory
npm install --omit=dev        # 除了 DSH 这个 peer，没有任何运行时依赖
```

把它加进你的 DSH profile 插件列表，然后重启 DSH 让模块加载。

验证加载是否干净：

```bash
node scripts/smoke-apply.mjs
```

它用一个假 ctx 跑一遍 `apply(ctx, config)`——和 DSH 启动时走的是同一条路。过了就说明不会把宿主搞崩。

## 配置

全部配置都是可选的，不配也能跑。**开箱时写入链和四股力门控已经是开着的**——这正是一次新安装能真正攒下记忆的原因。有两样默认关闭，因为它们要么不可逆、要么属可选项：冷宫归档（搬卡不可逆）与闪回。完整对照见[默认值](#默认值--开箱是什么状态)。

### 环境变量

| 变量 | 默认 | 用途 |
|---|---|---|
| `PM_DATA_ROOT` | `~/.dsh/unified-memory` | 卡库、索引、日志的位置 |
| `DSH_HOME` | `~/.dsh` | DSH 主目录（数据根从它推导） |
| `PM_DIARY_ROOT` | `<数据根>/diary` | 日记文件写入位置 |
| `PM_SESSIONS_ROOT` | `~/.dsh/sessions` | DSH 会话存储（事件溯源时读取） |
| `PM_DIARY_PROMPTS` | *未设* | 指向覆盖日记提示词的 JSON 文件 |

### 模型配置 —— 最容易踩的一节

**存在两套独立的模型端点，管的是不同的事。跳过这一节，插件看起来一切正常，但永远不会记住任何东西。**

| 配置块 | 驱动什么 | 缺失后果 |
|---|---|---|
| `llm:` | **产卡**（extract / distill） | **一张卡都不会生成。** 搜索能用，但库永远是空的。 |
| `embedding:` | 向量检索 | 退化成纯 BM25。仍可用，但对「换个说法」的召回变弱。 |

两者都不致命——插件是安静降级而不是崩溃。**恰恰因为安静，所以特别容易配错而不自知。**

#### 填在哪里

写在 `cordis.patch.yml` 的 `config:` 下：

```yaml
config:
  # ... 其他配置 ...

  # 想让记忆真正攒起来，这段是必需的
  llm:
    enabled: true
    baseUrl: 'http://127.0.0.1:8080/v1'
    apiKey: 'not-needed-for-local'
    model: 'your-model-name'
    maxTokens: 4000
    temperature: 0.2
    timeoutMs: 60000

  # 可选 —— 不填就是纯 BM25
  embedding:
    baseUrl: 'http://127.0.0.1:8080/v1'
    apiKey: 'not-needed-for-local'
    model: 'bge-m3'
    dimensions: 1024
```

两者都是标准 OpenAI 兼容端点，任何供应商都行——本地 llama.cpp / Ollama，或者云端 API。

`dimensions` 必须和你的 embedding 模型真实输出维度一致，否则向量索引会建错。

#### 另一条路：从 DSH profile 继承

如果你的 DSH profile 里已经有 `embedding:` 段，那就别在这里再写一份，指过去就行：

```yaml
config:
  profilePath: '~/.dsh/profiles/web/cordis.patch.yml'
```

密钥直接从那个文件读——**不会经过 agent 上下文，也不会写进日志。**

#### 快速自检

配好之后跑一下冒烟，看有没有 LLM 那一行：

```bash
node scripts/smoke-apply.mjs
```

如果 `llm:` 没配，插件会打一条 `ingest-llm-unavailable` 然后跳过产卡。**看到这行就等于「你的 key 没接上」。**

### 日记提示词

日记子系统自带的是**与角色无关的通用提示词**。想用自己的声音，把 `PM_DIARY_PROMPTS` 指向一个 JSON 文件：

```json
{
  "master": "用第一人称写今天的日记……",
  "self": "用第一人称写一页只给自己看的私记……"
}
```

## 注册了哪些工具

| 工具 | 作用 |
|---|---|
| `memory_search` | 搜索长期记忆 |
| `memory_get` | 取一张卡的全文 |
| `memory_refute` | 标记某条记忆是错的，并记录纠正 |
| `diary_write` | 写日记 |
| `diary_read` | 读最近的日记 |
| `diary_config` | 查看或修改日记开关 |
| `dispatch_send` | 派一单任务并开始跟踪 |
| `dispatch_scan` | 对账：跟踪中的任务到底是什么状态 |
| `dispatch_close` | 销账并留结论 |
| `hotreload_probe` | 只读自检（loader / fiber / entry） |
| `hotreload_dryrun` | 报告「如果要重载会做什么」，但不动手 |
| `hotreload_apply` | **永远拒绝执行** —— 见下 |

> **`hotreload_apply` 为什么拒绝：** 进程内自热重载被认真研究过，结论是**在没有外部重载器的前提下无法安全做到**。被 dispose 的 fiber 不留下任何活的 context 可供重新 apply，而且那条「保险」路径和它要保护的操作共享同一个失败原因。**「拒绝」本身就是这个功能。** 事故复盘写在 `lib/dispatch/hotreload-exec.js`。

## 数据长什么样

```
$PM_DATA_ROOT/
├── ingest/
│   ├── conversations/      L0 原始轮次
│   ├── records/            L1 提炼出的事实
│   ├── engrams.jsonl       L2 持久卡片
│   └── ongoing-thread.json 会话之间的交接快照
├── hypergraph/             情节 / 实体索引分片
├── embeddings/             向量索引
├── dispatch/               派单台账（预写日志，崩溃可恢复）
├── logs/                   诊断日志（轮转，有体积上限）
└── diary/                  日记状态与索引
```

**全是普通文件。** 你可以直接读、用 `cp -r` 备份、搬到另一台机器、或者删掉重来。没有数据库要迁移。

## 测试

```bash
npm run check                             # 四道便宜闸（见下表）
node selftest-dispatch-machine.mjs        # 跑单个套件
```

每道闸问的是不同的问题，且每一道都是因为别的闸漏掉过真问题才加上来的：

| 闸 | 问什么 | 什么时候会红 |
|---|---|---|
| `scripts/smoke-apply.mjs` | `apply()` 在假 ctx 上跑得通吗 | 插件会让宿主机启动就崩 |
| `scripts/check-tracked-imports.mjs` | `lib/` 引用的东西真的**提交**了吗 | 源码目录被 `.gitignore` 静默排掉 —— 本地测试全绿，全新 clone 必崩 |
| `scripts/check-syntax.mjs` | 每个已提交的 JS 文件**能不能解析** | 某个没人 import 的文件坏着躺在那儿 —— 它从不加载，别的检查都看不见 |
| `scripts/check-hardcodes.mjs` | 有没有哪条路径指向**我的机器** | 有 `C:/Users/…` 或没展开的 `~/…` 混进去 —— Node 不展开 `~`，它变成**相对路径**，会在你的目录里悄悄建一个名叫 `~` 的文件夹 |

共 **37 个测试套件**，覆盖接线、检索、渲染、跨源合并、缓存契约、派单状态迁移、日记行为、开箱默认值。需要**已有数据**的套件（卡库 / tdai 对话 / 画像文件 / 场景块）在全新安装上会**打印原因后跳过**——缺素材不是判据失败，更不能伪装成失败或伪装成通过。为确认"跳过"不是把坏掉的东西藏起来，这些套件另外拿一份**真实卡库的只读副本**重跑过：跨源 52/52、p4 70/70、ingest 430/430（2069 张卡）。

**全仓库一条铁律：不许写 `~/…`。** Node 不展开它。要路径就调 `lib/paths.js` 的 `dataPath()` / `dshHome()` / `sessionsRoot()`，或者写绝对路径——剩下的交给 `check-hardcodes`。

贯穿始终的设计原则：**每一个检查都要配一个真的会失败的负例。** 不会失败的检查不是检查。

## 安全模型

```bash
node scripts/security-audit.mjs    # 密钥、个人路径、私人内容、凭据文件
node scripts/data-leak-audit.mjs   # 真实卡片 ID、会话 ID、时间戳
```

**这个插件不做的事：**

- 没有遥测。不回家报到。
- 不存储凭据。API key 从你的 DSH profile 读，永不写日志。
- 数据不离开这台机器——除了发往*你自己*配置的那个 embedding 端点。

**你必须做的事：**

- 把 `$PM_DATA_ROOT` 排除在版本控制之外。自带的 `.gitignore` 已经处理了。
- 把数据目录当私密内容对待——里面是你的对话，明文。

## 默认值 —— 开箱是什么状态

首次启动时，插件会在 `$PM_DATA_ROOT/ingest/config.json` 生成一份配置模板，下面这些**默认已经打开**：

| 开关 | 默认 | 说明 |
|---|---|---|
| `enabled` / `capture` / `extract` / `distill` | **开** | 写入链从一开始就在跑 |
| `fourForcesEnabled` | **开** | 启用乘法门控 + 三档半衰期 |
| `flashbackEnabled` | 关 | 可选旁路，默认不启用 |
| `coldArchiveEnabled` / `coldArchiveAutoApply` | **关** | 搬卡是不可逆的物理动作，**故意不自动** |

改动生成的配置文件即可调整，**改完即时生效，不需要重启**。

想退回旧排序：把 `fourForcesEnabled` 改成 `false` —— 一个字段回滚，不用改代码。

## 已知边界

写出来，因为一个把话说太满的记忆系统比没有更糟：

| 边界 | 说明 |
|---|---|
| **依赖 DSH** | 不是独立服务。需要宿主提供会话、工具、持久化服务。 |
| **热重载做不到** | 进程内自重载不留活 context，必须完整重启 DSH。 |
| **向量可选** | 没有端点就是纯 BM25——精确词强，换说法弱。 |
| **产卡需要 LLM** | `capture` 和交接快照不需要；`extract` / `distill` 需要。 |
| **交接只有最后一轮** | `ongoing-thread.json` 只存一份快照，每轮覆盖。它是连贯性辅助，不是转录。 |
| **场景隔离默认关** | 未标注场景的卡永远可见。 |
| **假设单写者** | 两个进程写同一个数据根会冲突。 |
| **没有跨机同步** | 自己解决（它就是个文件夹，rsync 就够）。 |
